# CommuniQ — Fine-tuning pipeline

Fine-tune `meta-llama/Meta-Llama-3.1-8B-Instruct` with QLoRA on synthetic CommuniQ conversation data. Training runs on **Google Colab (free T4)** or any Linux CUDA machine. Inference uses **Ollama** locally.

---

## Step 1 — Generate synthetic training data

The pipeline ships with 20 hand-crafted sessions. **You need at least 100-200 to see meaningful improvement.** Use the bulk generator:

### Prerequisites
```bash
pip install groq   # or: pip install openai
```

### Set your API key
```powershell
# Windows PowerShell
$env:GROQ_API_KEY = "your_groq_key_here"
```
```bash
# Linux / macOS / Colab
export GROQ_API_KEY=your_groq_key_here
```

Get a free Groq key at https://console.groq.com (generous free tier).

### Run the generator
```bash
# Generate 200 sessions (~15-20 min, uses llama-3.3-70b-versatile on Groq)
python training/scripts/generate_bulk_dataset.py \
  --count 200 \
  --output training/data/sessions_bulk.json

# Resume if interrupted
python training/scripts/generate_bulk_dataset.py \
  --count 200 \
  --output training/data/sessions_bulk.json \
  --resume
```

The script generates sessions across **5 scenario types**:
- `hr_interview` — behavioural, strength/weakness, salary negotiation, cultural fit
- `technical` — system design, DSA, code review, debugging
- `gd` — group discussion on policy, business, current affairs topics
- `sales` — cold pitch, objection handling, executive pitches
- `client_handling` — angry escalation, expectation management, churn risk

Each session has **5 user quality profiles** (excellent → poor) so the model learns to behave differently with strong vs. weak candidates.

## Step 2 — Convert to ChatML JSONL

Merge the bulk sessions with the existing spectrum sessions and convert:

```bash
# Combine JSON files (PowerShell)
python -c "
import json
from pathlib import Path
files = ['training/data/sessions_spectrum_20.json', 'training/data/sessions_bulk.json']
all_sessions = []
for f in files:
    p = Path(f)
    if p.exists():
        all_sessions.extend(json.loads(p.read_text()))
Path('training/data/sessions_combined.json').write_text(json.dumps(all_sessions, indent=2))
print(f'Combined: {len(all_sessions)} sessions')
"

# Convert to ChatML
python training/scripts/firestore_turns_to_chatml.py \
  --input training/data/sessions_combined.json \
  --output training/data/chatml.jsonl
```

## Step 4 — Train / validation split

```bash
python training/scripts/split_train_val.py \
  --input training/data/chatml_scrubbed.jsonl \
  --out-dir training/data/split \
  --val-ratio 0.1
```

Expected output:
- `data/split/train.jsonl` — ~90% of examples
- `data/split/val.jsonl` — ~10% of examples

## Step 5 — Fine-tune (recommended: Google Colab)

### Option A — Google Colab notebook (easiest)

1. Upload `training/data/split/train.jsonl` and `val.jsonl` to Google Drive at `MyDrive/communiq/data/`
2. Open `training/train_colab.ipynb` in Colab: go to https://colab.research.google.com → **File > Upload notebook**
3. Set runtime: **Runtime > Change runtime type > T4 GPU**
4. Add your HuggingFace token as a Colab secret named `HF_TOKEN` (Key icon in left sidebar)
5. Run all cells top to bottom

The notebook trains for 2 epochs and saves the LoRA adapter to `MyDrive/communiq/lora_output/`.

**Free T4 estimate:**
| Dataset size | Time (1 epoch) | Time (2 epochs) |
|---|---|---|
| 100 examples | ~8 min | ~16 min |
| 200 examples | ~15 min | ~30 min |
| 500 examples | ~35 min | ~70 min |

### Option B — Local Linux machine (CUDA)

```bash
pip install unsloth trl datasets transformers accelerate bitsandbytes

python training/train_qlora_unsloth.py \
  --train training/data/split/train.jsonl \
  --output-dir out/lora \
  --epochs 2
```

## Step 6 — Export to GGUF + load into Ollama

After training, the Colab notebook can export to GGUF (Step 9 in the notebook). Then on your local machine:

### Download the GGUF from Drive

Download `MyDrive/communiq/gguf/communiq-8b-q4_k_m.gguf` to your PC.

### Create the Ollama Modelfile

Copy `training/Modelfile.communiq.example` to `Modelfile.communiq` and update the `FROM` path:

```
FROM ./communiq-8b-q4_k_m.gguf
```

### Register with Ollama

```bash
ollama create communiq:8b -f Modelfile.communiq
ollama run communiq:8b  # quick smoke test
```

### Point CommuniQ at the fine-tuned model

In `ai-server/.env`:
```
LLM_BACKEND=ollama
OLLAMA_MODEL=communiq:8b
```

In `pipecat-worker/.env`:
```
LLM_MODEL=communiq:8b
```

Restart the ai-server and pipecat-worker. The app will now use your fine-tuned model.

## Troubleshooting

**OOM on T4:** Reduce `MAX_SEQ_LENGTH` from 4096 to 2048 in the notebook, or reduce `BATCH_SIZE` to 1.

**`meta-llama` access denied:** Accept the license at https://huggingface.co/meta-llama/Meta-Llama-3.1-8B-Instruct and wait a few minutes before re-running.

**Bad generation quality after fine-tuning:** Common with <50 examples. Generate more data and retrain. Also check that your GROQ-generated sessions are realistic (inspect 10-20 manually before training).

**Groq rate limit during generation:** The generator has a `--delay 1.0` (1 second between calls). Increase to `--delay 2.0` if you hit 429 errors.
